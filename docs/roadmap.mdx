# Roadmap

Phases 1–7 form the current implemented renderer and optional persistence slice. Engine version `0.0.0-phase.7` carries the bounded image/section/header/footer/page-field profile forward and partitions render caches by exact compatibility inputs. The reference app adds anonymous-session Convex metadata and direct storage uploads while keeping persistence off by default. Phase 7 is implemented and hardening; it is not a claim of broad Word compatibility, complete cross-runtime proof, production authentication, or production readiness.

## Phase 4 — Implemented; hardening ongoing

- Relationship-owned numbering definitions and overrides; supported bullet, decimal, letter, Roman, multilevel/custom, and legal labels.
- Searchable source-linked labels, counter continuation/restarts, list indentation/wrapping, keep chains, keep-lines-together, and widow/orphan control.
- Nested whole-paragraph `if`/optional `else`/`each`, item-relative object fields, safe formatters, canonical loop manifest paths, deterministic nested schema/starter data, and cumulative limits.
- Explicit locale/time-zone formatter context with no ambient locale, time zone, or clock dependency.

## Phase 5 — Implemented; hardening ongoing

- Positive integer-twip `tblGrid` geometry with exact explicit `tblW`/`tcW` equality and deterministic default margins.
- Supported borders, clear-pattern solid shading, exact/at-least row heights, vertical alignment, `gridSpan`, and validated `vMerge` chains.
- Dedicated whole-row `if`/optional `else`/`each` blocks with structural header/merge safeguards and cumulative limits.
- Contiguous repeated headers, deterministic row fragmentation and `cantSplit` fallback diagnostics, source-linked traces, multi-page searchable output, and deterministic PDF strokes.
- Explicitly excluded: percentage widths, nested tables, table styles/themes, complex shading, and complete Word autofit. Static images in supported cell paragraphs arrive in Phase 6.

## Phase 6 — Implemented; hardening ongoing

- Internal relationship-owned PNG/JPEG content with explicit positive inline dimensions, immutable bytes, source links, exact MIME/signature/dimension/profile validation, and count/byte/side/pixel/decoded-work limits.
- Deterministic image preparation and exact-content deduplication; PDF image XObjects use DCT for JPEG, Flate for normalized PNG planes, and grayscale `/SMask` objects for alpha.
- Multiple deterministic `nextPage` sections with portrait/landscape page geometry and matching per-page PDF `MediaBox` values.
- Inherited default headers/footers with exact edge-relative distances (720-twip defaults), static images, reusable template values/formatters/paragraph blocks, and global decimal `PAGE`/`NUMPAGES` fields.
- Binary-safe workspace-PDF validation that follows classic xref offsets and stream lengths, validates upright text/image resources, and extracts searchable per-page text.
- Explicitly excluded: dynamic image tags/fetches, anchors/floating placement, crop, rotation, SVG, broad image profile/color conversion, continuous/odd/even breaks, first/even header variants, automatic header/footer numbering, and arbitrary fields.

## Phase 7 — Implemented; hardening ongoing

- Anonymous browser sessions through `convex-helpers`, with every template, render, cache read, and delete scoped to the session.
- Direct generated upload URLs for browser-to-Convex DOCX/PDF storage; storage IDs, bounded metadata, diagnostics summaries, and deterministic hashes remain in database documents.
- Cursor-paginated history, bounded realtime recent status, completed-PDF cache reuse, owned bearer-URL reads, and scheduled cascading deletion of rows plus storage objects.
- Explicitly excluded: production authentication/tenant policy, perfect abandoned-upload reclamation, rate limiting, retention compliance, live deployment proof, and treating storage URLs as fine-grained authorization.

## Future phases

The ordering below preserves the original project brief.

### Phase 8 — Landing page and documentation

Complete the polished landing page, Mintlify documentation routes, interactive examples, architecture explanation, support matrix, GitHub/community links, and SEO metadata, with representative redistributable authoring fixtures and browser proof.

### Phase 9 — Hardening

Add security fixtures, fuzz/property testing, cross-runtime and real-browser determinism, performance benchmarks, Vercel verification, accessibility evidence, package-size review, and a formal public API review.

### Phase 10 — Release preparation

Add Changesets, publishable package builds, prerelease versioning, provenance configuration, release documentation, contribution materials, a reconciled roadmap, and an initial prerelease. Publication and live deployment remain approval-gated.

Each feature must enter through the staged architecture. Current focused tests establish the local Phase 7 Convex boundary but do not establish broad Microsoft Word fixture coverage, full Bun/Node/browser equivalence, broad image/color-profile equivalence, production authentication, deployment proof, or production readiness.
