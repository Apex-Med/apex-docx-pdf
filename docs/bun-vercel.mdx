This repository is a Bun workspace monorepo. Its current scripts live at the repository root and in `apps/web`.

## Local commands

```bash
bun test
bun run test:cross-runtime
bun run test:browser-determinism
bun run test:playground-smoke
bun run typecheck
bun run build
bun run dev
bun run convex:dev
```

Run `bun run dev` to start the Turbo application tasks. The playground renders locally and exposes no cloud-persistence controls. `bun run convex:dev` remains available only for developing the unmounted future persistence foundations.

The web app uses the browser package and a module worker. The checked-in runtime-neutral release suite reuses deterministic synthetic fixture builders for plain template formatting, multi-page template-table row expansion, and static PNG/JPEG rendering with sections, headers, and footers. It also checks a missing-required-data rejection with stable engine and diagnostic codes. The Bun/Node gate bundles that compact suite once, runs it in two separate Bun processes and Node 24, and requires exact agreement with canonical page counts, searchable text, PDF-validity flags, PDF hashes, and layout-trace hashes. The browser-determinism gate verifies the same canonical evidence through the production module worker in real headless Chromium. CI installs Chromium and runs both gates.

The separate playground smoke drives the actual application through a three-page upright render, `%PDF-` download, form/JSON synchronization, invalid-data guard, stale-result invalidation, reset actions, and mobile keyboard tabs with zero runtime errors. Hosted smoke additionally covers the migrated four-page K3 template. Together these checks prove only the bounded release suite and recorded Chromium walkthroughs. They are not broad browser, Word-fixture, or operating-system proof. The worker installer accepts explicit engine options, including caller-supplied font bytes; loading bundled application font assets remains outside the renderer. DOCX images are package-owned bytes and require no runtime fetch.

## Vercel status

The TanStack Start application uses the current `nitro/vite` adapter and a Bun-targeted root Build Output API configuration. Nitro pins `runtime: "bun1.x"` and `maxDuration: 30`. The approved production deployment is live at `https://pdf-docx.apexmed.dev`; Vercel reports one 1.16 MB Bun function, and the canonical domain is verified. `VITE_SITE_URL` is configured while Convex and Mintlify URLs are intentionally absent. Exact deployment and smoke evidence is in `reports/deployment-review.md`.

When deploying, keep the renderer’s explicit-input contract intact: package bytes and data should reach an application-owned endpoint or worker boundary; locale, time zone, metadata, limits, and authorization must be explicit. Do not turn deployment configuration into an implicit source of fonts, locale, clock data, or network template execution.
