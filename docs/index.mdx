Apex DOCX PDF renders a deliberately documented DOCX profile to searchable PDF. It is not a Word clone: unsupported or materially lossy source content is diagnosed with source location instead of being silently discarded.

Phases 1–8 now form a working renderer, local-only reference application, and Mintlify documentation source. Engine compatibility version `0.0.0-phase.8` carries bounded package-owned inline PNG/JPEG images, mixed sections, inherited headers/footers, page fields, tables, templates, numbering, and explicit fonts through the deterministic renderer. Local Phase 9 hardening evidence and Phase 10 prerelease preparation are checked in. The playground is deployed on Vercel; Mintlify hosting and npm publication remain separate.

<Warning>
  The supported profile remains intentionally bounded. Canonical dynamic image
  values require explicit bytes and dimensions; image fetches, anchors/floating
  placement, crop, rotation, SVG, broad image profile/color conversion,
  continuous/odd/even section breaks, first/even headers, automatic
  header/footer numbering, nested tables, complete Word autofit, complex-script
  shaping, and CFF embedding are not implemented. Phase 7 is not a broad Word,
  cross-runtime, production-authentication, or production-readiness claim. The
  hosted playground is verified, but it is not a persistent SaaS,
  production-authentication, operational-SLO, or broad compatibility claim.
</Warning>

## Product and playground links

The public local-only playground is [pdf-docx.apexmed.dev](https://pdf-docx.apexmed.dev), with the interactive workspace at [pdf-docx.apexmed.dev/playground](https://pdf-docx.apexmed.dev/playground). The Mintlify deployment remains independent and is not yet configured as the application's canonical documentation origin.

The examples in these docs use Mintlify tabs and accordions to make template patterns easier to compare. They do not embed the renderer. Use the local-only playground inspector to compile a real DOCX, inspect its generated contract and diagnostics, and render representative data before production use.

## Design contract

The renderer treats template bytes, bounded JSON data, caller-supplied font configuration and bytes, engine version, locale, time zone, metadata, limits, and explicit render options as compatibility inputs. Formatter output uses bounded engine-owned `en-US`/`en-ZA` locale profiles plus the explicit IANA time zone and never consults ambient locale data, time zone, or clock state. See [determinism](/determinism) and the [architecture](/architecture) for the full boundary.
