# Apex DOCX PDF

Apex DOCX PDF renders a deliberately documented DOCX profile to searchable PDF. It is not a Word clone: unsupported or materially lossy source content is diagnosed with source location instead of being silently discarded.

Phases 1–3 now form a working renderer slice: ordinary main-document paragraphs, inline value placeholders, document styles, paragraph geometry, and caller-supplied TrueType fonts render to searchable PDF. Page dimensions and margins come from the document's final body-level section properties, with A4 dimensions used when page-size values are absent or invalid.

<Warning>
  The supported profile remains intentionally small. Tables, conditional and
  loop tags, images, headers, footers, complex-script shaping, Convex wiring,
  and deployment are not implemented.
</Warning>

## Product and playground links

This documentation repository intentionally does not declare a public product or playground URL. The local web app includes a `/playground` route, but a Mintlify deployment may be hosted on a different origin. Configure any product or playground link at deployment time, once its canonical URL is known.

## Design contract

The renderer treats template bytes, data, caller-supplied font configuration and bytes, engine version, locale, time zone, metadata, and explicit render options as compatibility inputs. It does not discover system fonts or fetch font resources. Identical inputs are intended to produce identical layout traces and byte-identical PDFs. See [determinism](/determinism) and the [architecture](/architecture) for the full boundary.
