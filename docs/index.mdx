# Apex DOCX PDF

Apex DOCX PDF renders a deliberately documented DOCX profile to searchable PDF. It is not a Word clone: unsupported or materially lossy source content is diagnosed with source location instead of being silently discarded.

Phases 1–7 now form a working renderer and optional persistence slice. Engine version `0.0.0-phase.7` carries bounded package-owned inline PNG/JPEG images, mixed sections, inherited headers/footers, page fields, tables, templates, numbering, and explicit fonts through the deterministic renderer; the reference app adds opt-in session-owned Convex storage and cache metadata without coupling Convex to the engine.

<Warning>
  The supported profile remains intentionally bounded. Dynamic image tags, image
  fetches, anchors/floating placement, crop, rotation, SVG, broad image
  profile/color conversion, continuous/odd/even section breaks, first/even
  headers, automatic header/footer numbering, nested tables, complete Word
  autofit, complex-script shaping, and CFF embedding are not implemented. Phase
  7 is not a broad Word, cross-runtime, production-authentication, or
  production-readiness claim.
</Warning>

## Product and playground links

This documentation repository intentionally does not declare a public product or playground URL. The local web app includes a `/playground` route, but a Mintlify deployment may be hosted on a different origin. Configure any product or playground link at deployment time, once its canonical URL is known.

The examples in these docs use Mintlify tabs and accordions to make template patterns easier to compare. They do not embed or claim a live renderer. Use the local playground inspector to compile a real DOCX, inspect its generated contract and diagnostics, and render representative data before production use.

## Design contract

The renderer treats template bytes, bounded JSON data, caller-supplied font configuration and bytes, engine version, locale, time zone, metadata, limits, and explicit render options as compatibility inputs. Formatter output uses only explicit `Intl` context and never consults ambient locale, time zone, or clock state. See [determinism](/determinism) and the [architecture](/architecture) for the full boundary.
