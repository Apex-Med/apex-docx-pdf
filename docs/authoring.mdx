# Authoring guide

The renderer accepts one ordinary DOCX main document and normalizes its paragraphs, styles, and text runs before templating and layout. Keep templates within the documented profile and make unsupported content an intentional future migration, not an assumption.

## Supported authoring shape

- Use paragraphs and text runs in the main document.
- Use inline value tags in paragraph text, for example `{{invoice.number}}`.
- Set the final body-level section's page size and margins deliberately. Missing or invalid page-size values fall back to A4 dimensions.
- Use document defaults, paragraph and character styles, `basedOn` inheritance, and direct run formatting for the supported properties.
- Configure every required font face explicitly. Keep text to well-formed left-to-right Latin and ensure the supplied TrueType program contains each required glyph.
- Avoid tabs; tab-stop layout is not implemented.

## Use explicit value types where helpful

```text
Invoice: {{invoice.number:string}}
Amount: {{invoice.total:number}}
Paid: {{invoice.paid:boolean}}
Issued: {{invoice.issuedAt:date}}
```

An untyped tag is permitted, but explicit types make generated schema and data validation more useful. Each field is required by the generated JSON Schema.

## Preserve an inspectable template

Use semantic paths such as `customer.address.city`; avoid dynamic expressions, helpers, or arbitrary code. Compilation reports malformed tags, unsafe paths, and incompatible explicit types as source-located error diagnostics on the returned compiled template. Inspect them before calling render.

<Tip>
  Save a representative template fixture with known data and keep its layout
  trace/PDF as a regression artifact. This makes intentional renderer changes
  distinguishable from accidental drift.
</Tip>

## Do not rely on these yet

Tables, images, headers, footers, conditions, loops, image tags, keep-with-next, widow/orphan controls, and complex scripts are outside the current profile. The correct behavior is a diagnostic or fallback where documented—not a best-effort recreation of Word.

See [template language](/template-language) for grammar and [font handling](/font-handling) for explicit registration and embedding behavior.
