---
title: "Browser usage"
description: "Run the same renderer in a Web Worker without uploading the document."
---

`@apexmed/browser` wraps the same engine packages used by Bun and Node. A Web Worker owns compilation and rendering so the UI thread can remain responsive.

The Phase 3 `@apexmed/fonts` adapter is browser-safe, and the worker carries the current template, numbering, fixed-grid table, static-image, section/header/footer, page-field, and PDF path through the same engine API. The worker installer accepts explicit engine options, or a promise for them, so an application can resolve its bundled font assets to `Uint8Array` values before the engine is created. Font acquisition remains application-owned. Static document images come only from internal DOCX parts; neither the engine nor its font/image packages discover system resources, read the filesystem, or fetch the network.

## Install the worker

```ts
// render.worker.ts
import { installRendererWorker } from "@apexmed/browser/worker"

const engineOptions = loadApplicationOwnedFontConfiguration()
installRendererWorker(undefined, engineOptions)
```

`loadApplicationOwnedFontConfiguration()` represents application code that returns `EngineOptions` or a promise for it. It must supply the exact font bytes and a fallback family; without `fonts`, the worker uses the historical Helvetica fallback.

## Create a client

```ts
import { BrowserRendererClient, ObjectUrlLease } from "@apexmed/browser"

const worker = new Worker(new URL("./render.worker.ts", import.meta.url), {
  type: "module",
})
const renderer = new BrowserRendererClient(worker)
const lease = new ObjectUrlLease()

const compiled = await renderer.compile(templateBytes, {
  onProgress: (event) => console.log(event.stage, event.message),
})

const rendered = await renderer.render(
  compiled.templateHash,
  {
    invoice: {
      showItems: true,
      items: [{ description: "Consultation", amount: 1250 }],
    },
  },
  { locale: "en-ZA", timeZone: "Africa/Johannesburg" }
)

const pdfUrl = lease.replace(rendered.pdf.slice().buffer, "application/pdf")
// Use pdfUrl in an iframe or download link, then call lease.revoke() when done.
```

## Lifecycle and cancellation

Pass an `AbortSignal` to `compile` or `render` to send a cancellation message to the worker. A worker retains compiled templates by template hash for its own lifetime; recompile after disposal or reload. Call `renderer.dispose()` during UI teardown and revoke object URLs to release browser resources.

The repository's local-only playground follows this pattern and renders in a worker. Its application layer self-hosts hash-pinned static TrueType faces for Inter, Instrument Sans, Instrument Serif, Geist, Geist Mono, and Bricolage Grotesque, loads those exact asset bytes before engine creation, and explicitly aliases familiar DOCX family names to catalog families. Every published static weight is included, and the visible font specimens use the same assets. That asset loading is reference-application behavior, not an engine network capability: there is no OS lookup, font CDN request, or uploaded embedded-font ingestion. The playground is deployed at `https://pdf-docx.apexmed.dev/playground`; focused hosted Chromium evidence does not establish a complete browser matrix or production SaaS boundary.
