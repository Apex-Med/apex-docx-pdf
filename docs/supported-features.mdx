# Supported features

The renderer supports a small, documented DOCX profile. A feature being common in Word does not make it supported here.

| Area | Phase 1 status | Behavior |
| --- | --- | --- |
| DOCX package validation | Supported | Validates ZIP structure, paths, size/entry/decompression limits, relationships, XML, and required parts. |
| Main-document paragraphs | Supported | Normalized and laid out on A4 pages. |
| Text runs | Supported | Text is preserved as positioned, searchable PDF text. |
| Inline value tags | Supported | Dotted paths with optional `string`, `number`, `boolean`, or `date` annotations. |
| JSON Schema and starter data | Supported | Generated at compile time from discovered fields. |
| PDF output | Supported | Deterministic PDF 1.7 using built-in Helvetica and WinAnsi text. |
| Layout trace | Supported | Optional source-linked page, line, block, overflow, and page-break data. |
| Tables | Planned | Not part of the current supported document profile. |
| Conditions and loops | Planned | Block tags are rejected. |
| Images | Planned | Image tags are rejected. |
| Headers and footers | Planned | Not part of the Phase 1 profile. |
| Full/custom font embedding | Planned | Current output uses built-in Helvetica only. |
| Convex integration | Planned | No repository Convex module or adapter exists yet. |
| Vercel deployment | Planned | No deployment configuration is supplied in this repository. |

## Current fidelity limits

DOCX font-family changes receive Helvetica-compatible measurement and PDF fallback warnings. Bold, italic, and underline text is retained as text but styling is not preserved. Text outside the current WinAnsi encoding is an error and that glyph run is omitted rather than substituted silently.

<Warning>
Treat diagnostics as part of the rendering contract. A successful PDF file is not evidence that every Word feature was represented.
</Warning>
