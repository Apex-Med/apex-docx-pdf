title: "Supported features"
description: "An honest compatibility matrix for the implemented Phase 7 renderer and demo adapter."
---

Engine version `0.0.0-phase.7` supports a bounded DOCX profile and partitions the optional app cache by exact engine/template/font/data/options hashes. A feature being common in Word does not make it supported here.

| Area                                | Status                       | Behavior                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DOCX package validation             | Supported                    | Validates ZIP structure, paths, limits, XML, relationship roots, external relationships, and the root office-document relationship; unconditionally rejects VBA/macros, OLE/embedded objects, ActiveX, attached packages or executables, templates/toolbars, custom UI, web extensions/task panes, and alternative-format chunks. |
| Main-document paragraphs            | Supported                    | Preserves supported paragraphs/runs in source order across one or more sections. Missing page geometry uses A4-profile defaults.                                                                                                                                                                                                  |
| Styles and paragraph formatting     | Supported with limits        | Resolves `docDefaults`, default paragraph/character styles, `basedOn`, direct formatting, indents/alignment/spacing, keep controls, widow/orphan control, and page-break-before.                                                                                                                                                  |
| DOCX numbering and list layout      | Supported with limits        | Relationship-owned definitions/overrides, supported formats/restarts, searchable source-linked labels, indentation/wrapping, and deterministic counters.                                                                                                                                                                          |
| Registered fonts and embedded text  | Supported with limits        | Library: explicit TrueType bytes and LTR Latin shaping. Playground: five application-owned, hash-pinned OFL TrueType families with deterministic aliases and no uploaded embedded-font execution. Searchable upright Type0/CIDFontType2 output; complete fonts, not true subsets.                                                 |
| Template values and formatters      | Supported with limits        | Typed dotted paths plus `upper`, `lower`, `currency:"ISO"`, and `date:"d MMMM yyyy"` using explicit locale/time-zone context.                                                                                                                                                                                                     |
| Conditions and loops                | Supported with limits        | Nested whole-paragraph and dedicated whole-table-row `if`/optional `else`/`each`; item-relative object fields and cumulative limits.                                                                                                                                                                                              |
| Fixed-grid tables                   | Supported with limits        | Positive integer-twip `tblGrid`, exact explicit `tblW`/`tcW`, supported margins/borders/shading/heights/alignment/spans/merges, repeated headers, and deterministic fragmentation.                                                                                                                                                |
| Static inline images                | Supported with limits        | Internal relationship-owned PNG/JPEG parts, explicit positive DrawingML extents, stable source links, immutable bytes, and optional locked-aspect validation. Supported in ordinary paragraphs, bounded table cells, headers, and footers.                                                                                        |
| Image resource limits               | Supported                    | Defaults: 100 distinct parts, 20,000,000 total bytes, 100,000 pixels per side, 100,000,000 pixels per image, 10,000 chunks/markers, and 400,000,000 decoded working bytes.                                                                                                                                                        |
| PNG profile                         | Supported with limits        | Non-interlaced legal grayscale/RGB/indexed/gray-alpha/RGBA depths; validated CRC/order/palette/transparency/scanlines/filters; normalized to 8-bit gray/RGB plus optional alpha. | PDF image output                    | Supported                    | Deterministic exact-content deduplication, per-page XObject resources, `/DCTDecode` JPEG, `/FlateDecode` PNG planes, optional grayscale alpha `/SMask`, positive placement matrices, and source-linked placements.                                                                                                                |

Positive portrait/landscape geometry produces the corresponding per-page PDF `MediaBox`.                                                                                                                                                          |
| Default headers and footers         | Supported with limits        | Internal default references inherit across sections until replaced. Exact edge-relative header/footer distances default to 720 twips and must fit inside body margins.                                                                                                                                                            |
| Header/footer templates             | Supported with limits        | Reusable definitions support paragraph values, safe formatters, bounded whole-paragraph blocks, static images, and page fields. Automatic paragraph numbering is unsupported.                                                                                                                                                     |
| `PAGE` and `NUMPAGES`               | Supported with limits        | Simple or complete complex fields; decimal/no-op switches only. Column breaks, float-clearing variants, and page breaks in tables or headers/footers fail with source-located content-loss diagnostics.                     |
| Word tabs and tab stops             | Supported with limits        | `w:tab` requires an explicit resolved paragraph stop with a positive integer-twip position, left/start alignment, and no leader. Stops are sorted deterministically; duplicate, clear, non-left, leader, missing-next-stop, and default-tab behavior are rejected rather than approximated.                                       |
| Highlight and script text           | Supported with limits        | The fixed Word highlight palette plus explicit `none` is retained and painted behind text. Baseline, superscript, and subscript are retained; scripts render at two-thirds size with fixed integer-twip shifts while PDF text remains upright and searchable. Unknown values fail at the source property.                         |
| Determinism and source links        | Supported with limits        | Stable semantic/display IDs, source-ordered collections, exact image collision checks, deterministic XObject/resource ordering, searchable page text, byte-repeatable PDFs, and optional source-linked traces. Checked-in PDF/trace goldens match across separate Bun processes, Node 24, and a real Chromium module worker.      |
| Binary-safe testkit                 | Supported for workspace PDFs | Follows classic xref offsets and direct stream lengths, excludes binary payloads from syntax checks, validates page image resources/upright text transforms, and extracts per-page searchable text. It is not a general PDF parser.                                                                                               |
| Dynamic image tags                  | Supported with limits        | Canonical `{{@image path}}` values accept explicit PNG/JPEG bytes, pixel dimensions, physical twip bounds, optional aspect preservation, and semantic alt text. URLs and non-canonical image tags are rejected; PDFs remain untagged.                                                                                             |
| Floating/cropped/transformed images | Unsupported                  | Anchors/floating placement, crop, rotation, and other DrawingML transformations are outside the profile.                                                                                                                                                                                                                          |
| SVG and broad image conversion      | Unsupported                  | SVG, CMYK/YCCK, ICC conversion, arbitrary PNG/JPEG profiles, and general color management are not implemented.                                                                                                                                                                                                                    |
| Other section/header variants       | Unsupported                  | Continuous, odd-page, and even-page breaks; first/even headers/footers; automatic header/footer numbering; and arbitrary Word fields are unavailable.                                                                                                                                                                             |
| Other table features                | Unsupported                  | Percentage widths, nested tables, styles/themes/conditional regions, complex shading, and complete Word autofit are unavailable.                                                                                                                                                                                                  |
| Other text/font features            | Unsupported                  | Default or non-left tab behavior, tab leaders, floating-object break clearing, complex scripts/bidi, CFF PDF embedding, and true default font subsetting are unavailable.                                                                                                                                                         |
| Opt-in Convex persistence           | Supported with limits        | The configured playground mounts tested anonymous-session storage, upload-intent registration/cleanup, metadata, cache, realtime, and deletion adapters behind an explicit disabled-by-default control. This is demo isolation, not production authentication.                                                                    |
| Hosted deployment                   | Planned                      | No production Vercel deployment, production Convex authorization, canonical hosted playground, or operational readiness claim has been verified.                                                                                                                                                                                  |

## Evidence boundary

Focused tests and runtime gates establish this supported slice. The compact release suite requires exact Bun/Node 24/real-Chromium-module-worker agreement for plain template formatting, multi-page table row expansion, static PNG/JPEG documents, and a stable missing-data rejection. Canonical success evidence includes page count, searchable text, PDF validity and hash, and layout-trace hash. This does not establish broad Microsoft Word fixture compatibility, equivalence across every runtime/version/document, production readiness, or full font/image-profile coverage. Synchronous PNG inflate is bounded but cannot observe cancellation until the call returns.

<Warning>
  Treat diagnostics as part of the rendering contract. A successful PDF is not
  evidence that every Word feature was represented.
</Warning>

## Unsupported-feature modes

`engine.compile(bytes, { unsupportedFeatures })` defaults to `strict`. The
mode changes only explicitly documented parser fallbacks; it never relaxes ZIP,
XML, package-security, resource-limit, invalid-value, ambiguous-layout, image,
or template-language errors.

| Mode         | Exact behavior                                                                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `strict`     | Rejects every unsupported feature.                                                                                                                                                                                    |
| `compatible` | May ignore Word's `lastRenderedPageBreak` pagination hint because the engine deterministically paginates the supported document model itself. The compiled template retains a structured warning naming the fallback. |
| `lenient`    | Includes compatible fallbacks and may replace `softHyphen` with an explicitly empty inline. Surrounding text remains in source order, and the compiled template retains a structured warning naming the replacement.  |

Every accepted fallback emits `DOCX_UNSUPPORTED_FEATURE_FALLBACK` with warning
severity and `mode`, `feature`, and `fallback` details. Unclassified blocks or
inlines, invalid tables/styles/sections, unsafe images, and any diagnostic that
would otherwise omit or ambiguously reinterpret meaningful content still fail
in all three modes with an error and `DOCX_CONTENT_LOSS` where applicable.
