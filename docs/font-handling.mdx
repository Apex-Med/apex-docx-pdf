# Font handling

Phase 3 adds explicit caller-supplied font registration. Pass a `FontConfiguration` when creating the engine; the exact face metadata, aliases, fallback family, and immutable font bytes become compatibility inputs. When no font configuration is supplied, the historical built-in Helvetica/WinAnsi fallback remains available.

## Configure font bytes explicitly

```ts
const fonts = {
  faces: [
    {
      family: "Example Sans",
      weight: 400,
      style: "normal",
      bytes: exampleSansBytes,
    },
  ],
  fallbackFamily: "Example Sans",
} as const

const engine = await createDocxPdfEngine({ fonts })
```

The fallback family must contain a 400 normal face. Faces support weights 400 and 700 and styles `normal` and `italic`. Optional aliases resolve to registered families. The engine snapshots supplied `Uint8Array` values and the font registry exposes a deterministic hash.

No part of this path discovers system fonts, reads font files, fetches a font URL, or depends on Node.js `Buffer`. The application owns acquisition of the bytes and must have the right to embed and distribute them.

## Deterministic matching

Within a requested or aliased family, matching uses this order:

1. Exact weight and style.
2. Weight 400 in the requested style.
3. Requested weight in normal style.
4. Weight 400 in normal style.

If the family has no match, the same sequence is applied to the configured fallback family.

## Shaping and embedding

Exact-pinned `fontkit` 2.0.4 parses font metrics and shapes well-formed left-to-right Latin text. Complex scripts, right-to-left text, and bidirectional layout are outside the current boundary.

For TrueType, the PDF serializer emits a Type0 font with a CIDFontType2 descendant, FontDescriptor, FontFile2 stream, CIDToGIDMap, and ToUnicode CMap. Each shaped glyph receives an absolute PDF position, preserving fontkit advances and offsets while keeping text searchable.

By default, the registry embeds the complete immutable TrueType program and returns `subsetted: false`. There is an injectable deterministic subsetting seam with an explicit source-to-subset glyph mapping, but the repository does not provide true font subsetting today. OpenType/CFF is diagnosed as unsupported for PDF embedding.

## Historical fallback

Without `FontConfiguration`, the Phase 1 path still measures and serializes built-in Helvetica with WinAnsi encoding. Non-Helvetica family and style requests produce compatibility warnings. Characters outside WinAnsi produce an error, and the high-level engine returns no render result rather than exposing an incomplete PDF.

Read [ADR 0004](/adr/0004-fontkit-full-font-embedding) for the dependency, licensing, determinism, and full-embedding decision.
